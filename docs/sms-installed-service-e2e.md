# SMS installed-service acceptance

Literal acceptance path:

`independent handset → operator-owned carrier number → real carrier-signed webhook → installed resident daemon → telephony-owned credential boundary → SMS shadow channel → pairing/approval → durable ingress/job → real daemon agent/model → send_message → durable outbox → production carrier send_sms → carrier message id → carrier delivery receipt → independent handset receives reply → handset sends exact hidden-nonce reply back → real signed inbound confirmation`

SMS deliberately does not own a second credential. A telephony account owns the carrier account, number and secret; adding that number automatically creates the SMS channel account with the same account id. Inbound texts are normalized by the production carrier implementation and enter the same channel ingress gate as Telegram/Slack/etc. Outbound text goes through the SMS adapter built from the telephony row and its native credential.

Supported live carriers are the production providers already shipped by Little Monkey:

- Twilio
- Telnyx
- Plivo

The deterministic `mock` carrier is useful for unit tests but is explicitly forbidden as literal E2E evidence.

## Required environment

```text
LITTLE_MONKEY_REQUIRE_SMS_INSTALLED_SERVICE_E2E=1
SMS_E2E_CARRIER=twilio|telnyx|plivo
SMS_E2E_CARRIER_ACCOUNT_ID=<Twilio Account SID / Telnyx carrier identifier / Plivo Auth ID>
SMS_E2E_FROM_NUMBER=+15550000000
SMS_E2E_CREDENTIAL=<operator-owned carrier credential>
SMS_E2E_PUBLIC_BASE=https://<public-host-routing-to-this-machine>
SMS_E2E_WEBHOOK_PORT=38447
```

For Telnyx also provide the public Ed25519 webhook key from the Telnyx portal:

```text
SMS_E2E_WEBHOOK_PUBLIC_KEY=<base64 public key>
```

The carrier credential is written only through `monkey telecom set-token` stdin and lives in the OS credential store. The harness never constructs `SmsAdapter`, `TwilioProvider`, `TelnyxProvider` or `PlivoProvider`, and never uses the target carrier credential to manufacture an inbound request.

## Carrier configuration

The harness creates an isolated telephony account, so its account id—and therefore callback path—is generated per run. It prints the exact production callback URL returned by:

```bash
monkey telecom callback-url <account-id> --json
```

Configure the operator-owned number's inbound SMS/MMS webhook to that exact URL. The public origin must route to `127.0.0.1:$SMS_E2E_WEBHOOK_PORT` on the machine running the installed daemon.

Twilio and Plivo signatures bind the callback URL, so the public base configured in Little Monkey must be the same canonical URL the carrier posts to. Telnyx uses its published Ed25519 webhook key. No unsigned or locally fabricated callback counts.

Outbound sends use the production status callback path automatically. The literal pass waits for the carrier's real delivery receipt to update the exact sent message to `delivered`; API acceptance alone is insufficient.

## Run

```bash
node scripts/ensure-cli-sidecar-placeholder.mjs
cargo build --locked --manifest-path src-tauri/Cargo.toml --bin monkey-cli
node scripts/ensure-cli-sidecar-placeholder.mjs
cargo run --locked --manifest-path src-tauri/Cargo.toml --example sms_installed_service_e2e
```

## Evidence required for a pass

1. The carrier credential probes successfully through the production telephony provider.
2. The telephony account and its SMS shadow channel are enabled and the real user service is installed.
3. The installed service has a resident PID and survives a stop/start with a different PID.
4. An independent handset sends the first unique marker through the real carrier.
5. The carrier's authentic callback becomes a durable inbound event, but the unknown E.164 sender receives no ingress/job under the default pairing policy.
6. That provider-derived sender id is approved using the normal `channels approve` command.
7. After daemon restart, the same handset sends the execution marker.
8. That exact message becomes a durable accepted ingress/job and reaches the real daemon model interface.
9. The real agent is offered and executes production `send_message`, then returns to the model after tool execution.
10. The reply becomes a durable outbound event with a real carrier message id rather than `local:*`.
11. A real carrier status callback marks that exact outbound telecom message `delivered`.
12. The harness then disables direct SMS execution. The handset must copy the SMS it actually received and send that exact text back unchanged.
13. That second real signed inbound must contain the hidden nonce generated by the model fixture, and must remain non-executing because direct access is disabled.

Steps 11–13 deliberately require both carrier-side delivery evidence and recipient-side observation. A carrier saying only that it accepted an API request is not 5/5 evidence.

## Public-app invariant

Nothing here requires a Little Monkey-owned phone number or carrier account. Each installer uses their own number and carrier account, just as they use their own Telegram bot, Slack app or Discord bot. Carrier secrets remain on the telephony account; the SMS channel never grows an independent credential.
